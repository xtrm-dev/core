# v0.15.1 — one-channel skill suggestions, compact cards, registry freshness

Package: `xtrm-tools@0.15.1` · Extensions: `@jaggerxtrm/pi-extensions@0.15.1`

> Patch on a minor: no new sb verbs, no new skills, no doctrine changes. What changed is how an already-shipped suggestion reaches the model and the operator, plus the release-mechanics fix that left main's freshness gate red after 0.15.0.

## Summary

0.15.1 removes the duplication in skill suggestions and finishes the house chrome. In 0.15.0 the input seam rewrote the operator's prompt *and* posted a card, so a skill load appeared twice — once as a house card, once glued into the operator's own message, where injected doctrine was indistinguishable from their words. The seam now posts a single labelled message and the message renderer draws the box, so the operator's prompt is never touched. Skill loads on the intention seam render as a one-row FYI card. The release also regenerates `.xtrm/registry.json` for the 0.15.0 version bump; without it `check:registry-freshness` failed on main and every pull request folded after it died in the check queue.

## Pi extensions

- **One channel for skill suggestions (574ae44 · #706).** The `input` seam no longer returns `action: "transform"`. It posts the labelled `<xtrm_context kind="skill-doctrine" source=… about=… by=… confidence=…>` block as its own message with `triggerTurn`, and the message renderer wraps that same content in the house box via `renderCardBox`. The model reads clean labelled text; the operator sees the dim purple box; the operator's words stay their words. Duty cards and the `agent_end` seam are unchanged.
- **Compact skill cards (0e625fc · #707).** Supersedes #703, which conflicted with #706. `formatSuggestionCard` takes `compact: true`: one interior row carrying verb, ref and confidence, with the instruction body dropped — that text already reached the model as the labelled message. The `agent_end` skill card passes `compact: true`; duty cards keep the two-row instruction form.
- **Registry freshness after a version bump (95a5a44 · #705).** `npm version` rewrites the package versions embedded in `.xtrm/registry.json`. The 0.15.0 release commit shipped without regenerating it, so the freshness gate failed on main. This release regenerates it; future releases must run `npm run gen-registry` in the same commit.

## Documentation

- README's `substrate-suggest` and `skill-suggest` sections now describe the shipped box chrome (dim purple `#8d7fe8` box, `(● suggestion)` title, italic interior, magenta-bold highlights on refs, commands and paths) and the labelled injection, instead of the pre-0.15.0 two-line card.
- The 0.15.0 notes carry a post-release corrections section recording #702, #705 and #706, so the published release body stays honest about what shipped after its tag.
