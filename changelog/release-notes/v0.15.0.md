# v0.15.0 — Jev suggestion extensions (substrate-suggest, skill-suggest), xt attach worktree discovery

Package: `xtrm-tools@0.15.0` · Extensions: `@jaggerxtrm/pi-extensions@0.15.0`

> Specialists compatibility is unchanged: `>=3.21.0 <5`. The vendored Specialists payload remains pinned to `master@5a661d16` (git-blob-sha1 digest).

## Summary

0.15.0 brings Jev-driven suggestion capabilities natively to Pi with two extensions: `substrate-suggest` and `skill-suggest`. `substrate-suggest` delivers at most one advisory Substrate duty or journal recommendation per turn in the house card style, with wait-guard external blocker detection, service-knowledge skill pointers, and tool nudges steering agents toward AST-grep, GitNexus, and the persistent Python kernel. `skill-suggest` ports the Jev skill-suggestion pattern directly over curated skills and nested reference doctrine across two seams: prompt transformation on `input` and follow-up doctrine injection on `agent_end`. Both extensions run deterministic gates before invoking Jev (Pi classifier with REST fallback to Typesafe System One), fail open, respect cooldowns, and log decisions to `~/.xtrm/*/log.jsonl`. This release also fixes `xt attach` to discover worktrees under `.xtrm/worktrees/` across all branch conventions with bounded slug matching and recency ordering.

## Pi extensions

- **`substrate-suggest` Jev-driven work duty suggestions (37216f2e, 6962f875, ad399b0f, a5ccec8e, 31b4cc96 · CORE-2345, CORE-2346, CORE-2348, #695).** Ranks Substrate duties (`claim_renew`, `close_due`, `revise_contract`, `checkpoint`, and `journal_*` kinds) at `agent_end` and renders at most one wake card per turn in the house style (purple `●` dot, dim state details, italic instruction with ignore-if-not-fits clause). In-session issue binding resolves automatically from observed claim tool calls, bash commands, dispatch results, recent refs, or live project claims. Includes wait-guard detection for unmonitored "wait for CI" commitments, service-knowledge skill pointers from `.xtrm/skills/<pack>/service-knowledge/service-registry.json`, mid-turn territory-hit advisories, and tool nudges that steer recursive `grep` and one-shot `python3` invocations toward `ast-grep`, `GitNexus`, and `python-kernel`. All suggestions are advisory and fail open, with per-scope cooldowns, decision logging to `~/.xtrm/substrate-suggest/log.jsonl`, and disable controls via `--no-substrate-suggest` or `SUBSTRATE_SUGGEST=off`.
- **`skill-suggest` two-tier Jev skill and doctrine suggestions (3b007b45, 78155fe8, b4945dd4, ec2a67f8 · #695).** Native Pi port of the Jev skill-suggestion pattern over curated skill packs. Builds a two-tier roster (curated skills from `SKILL.md` frontmatter plus nested reference doctrine from `references/*.md` first headings and summaries, capped at 60 entries). Operates across two seams: the `input` seam transforms the user prompt before the turn with a bounded `<skill_relevance>` block, and the `agent_end` intention seam inspects the agent's final message to inject relevant doctrine as a `followUp` read on the next turn. Uses a two-stage Jev classifier (`would_follow_documented_procedure` and `prose_suffices` gate nouls followed by Choice over the roster). Typed `/skill:<name>` commands remain fully functional, phase 1 keeps standard skill listings visible, decisions log to `~/.xtrm/skill-suggest/log.jsonl`, and suggestions can be disabled via `--no-skill-suggest` or `SKILL_SUGGEST=off`.
- **Two-stage Jev classifier client (37216f2e, 3b007b45 · #695).** Shared client querying Typesafe System One (Choice + Noul questions). Prioritizes Pi-native model registry classifiers (`ctx.modelRegistry.classify` with provider credentials from `auth.json`, preferring paid `jev-latest` before `jev-1.13-free`), falling back to direct REST requests with `TYPESAFE_API_KEY` or `~/.secrets/typesafe_api_key.txt`. All calls fail open to deterministic-only paths on timeout or network error.

## CLI

- **`xt attach` managed-root worktrees and slug matching (d1b86f70 · #697).** `listXtWorktrees` discovers worktrees under `.xtrm/worktrees/` regardless of branch naming convention (`feature/*`, `fix/*`, etc.), ensuring `auditWorktreePrs` and `restartAudit` see the full set. Session target matching resolves exact branch names, directory names, and hyphen-bounded directory suffixes (e.g., `7trm` resolves to `core-xt-pi-7trm`, while unbound `trm` is rejected). The interactive picker and default attach target sort by last activity (`lastLogTime ?? launchedAt` descending).

## UI

- **House suggestion cards and dot chrome (37216f2e, 13167868 · #695).** Suggestion cards and tool presentations use the purple `●` house dot glyph (`[38;2;141;127;232m●[0m`) with dim metadata and italic instructions, aligning `xtrm-ui` glyph assertions and extension renderers.
