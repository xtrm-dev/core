# v0.15.2 — compact renderer for labelled skill suggestions

Package: `xtrm-tools@0.15.2` · Extensions: `@jaggerxtrm/pi-extensions@0.15.2`

> Patch on a patch: one rendering defect, found by a live session rather than by the suite. The one-channel delivery shipped in 0.15.1 is unchanged; this fixes how it looked.

## Summary

0.15.1 moved skill suggestions to a single labelled `<xtrm_context>` message so the operator's prompt is no longer rewritten, but it rendered that message as-is inside the house box. In a live session the result was a broken frame: block lines exceed the card's maximum width, so padding went negative, the border clipped, and a six-line block of raw XML landed where the operator's prompt belonged. The model-facing content was always correct — only the operator-facing rendering was wrong. 0.15.2 parses the block the model receives and renders the compact card from it, so the two audiences finally differ in form as well as in purpose.

## Pi extensions

- **Compact card parsed from the labelled block (767164d · #709).** `parseContextBlock` reads `kind`, `source`, `about`, `by` and `confidence` out of the `<xtrm_context>` message body. The skill-suggest renderer uses those fields to draw the compact one-row card (`● suggestion` / `skill loaded · <id> · — · jev <n>`), with an intact frame and no raw XML on the operator's screen. The message body itself is unchanged, so the model still receives provenance-labelled context. Content that is not a labelled block falls back to the boxed raw form.

## Verification

- 40 skill-suggest tests (3 new: attribute extraction, non-block fallback to the raw box, framed one-row card with uniform row width and no `xtrm_context` text), 47 across both suggesters.
- The defect was found by visual test in a live session, not by the unit suite: the suite asserted the box math in isolation and never rendered a real block through the message renderer.
