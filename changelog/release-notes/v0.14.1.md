# v0.14.1 — agent host session history, live session status, retired hook cleanup

Package: `xtrm-tools@0.14.1` · Extensions: `@jaggerxtrm/pi-extensions@0.14.1`

> Specialists compatibility is unchanged: `>=3.21.0 <5`. The vendored Specialists payload remains pinned to `master@5a661d16` (git-blob-sha1 digest).

## Summary

0.14.1 extends the XTRM agent host for the xtrm-app client. The host serves the full Pi journal of a session through `GET /v1/sessions/:id/history`, so clients can project every Frame, not only the Frames left in the replay buffer. Session summaries now report the model, thinking level, context usage and repository. The device pairing messages move into `@xtrm/contracts`. All protocol changes are additive within their v1 schemas.

The agent host also gets three reliability fixes for prompts sent during Pi startup or never started. Claude Code hooks are now one process per event without exception, and runtime sync removes untagged registrations of retired hooks. `xt update --apply` no longer blocks user-scoped maintenance when a repository still has a legacy Beads board.

## Agent host

- **Session history route (75fedcb0 · XTRM-604).** `GET /v1/sessions/:id/history` returns the Pi journal entries (messages and compactions, active branch, oldest first) of a live or history-only session as `xtrm.agent-host-api.v1` `session_history`. The route is read-only. The journal must open with a Pi session header whose id matches the requested session. Strings above 64 KiB are cut and image data is dropped, with `truncated: true`. Claude sessions answer `history_unsupported`.
- **Session status and repository (e9cb82e6 · XTRM-603).** `session_identity` gains optional `repository` (owner/name) and `repositoryPath`. A new `session_status` payload carries `model`, `thinkingLevel` and `contextUsage`. The `xtrm-agent-host` extension sends it only when a value changes.
- **Repository for history-only sessions (5f0734c9 · XTRM-608).** Stopped sessions carry `repository` and `repositoryPath`, resolved from the session `cwd` behind an async cache, so they group by repository like live sessions.
- **Auth types in contracts (82fd5c42 · XTRM-599).** `xtrm.agent-host-auth.v1` (pairing and device messages) is now a schema in `@xtrm/contracts`. No behaviour change.
- **Pi startup window (2b2ed190 · XTRM-607).** The bridge counts a session as working from an idle submit or `before_agent_start` until `agent_start`. A second prompt in that window is rejected as busy. Steer, follow-up and abort are held and delivered on `agent_start` instead of starting a second run.
- **Prompt that never starts (0d82311b · XTRM-605).** When an accepted prompt opens no Frame within 60 s, the host clears the pending prompt and sends `command_result {status: failed, reason: prompt_not_started}`. Before, the session refused every later prompt as busy.

## Hooks and runtime sync

- **One process per Claude hook event (93c90513 · XTRM-592, #683).** The agent host reporter runs in-process inside `dispatch.mjs` instead of as its own Node process. Stop also runs the inbox reminder in-process. `policies/agent-host-reporter.json` and `policies/inbox-reminder.json` are removed.
- **Retired hook cleanup (372ebd51 · XTRM-602; bef29e9c · XTRM-606).** Runtime sync drops an untagged hook wrapper only when every command in it targets a retired `~/.xtrm/hooks` file: the inbox reminder, the old reporter and eight retired beads hooks. Mixed, unlisted and foreign wrappers are kept. Each removal is printed.

## CLI

- **`xt update` gated by blast radius (1bffe3d2 · CORE-2343, #688).** Repo-scoped writes stay blocked while a legacy `.beads` board is present. User-scoped maintenance (global skills payload, hook rewiring, prompt sync, Pi package assurance) now runs anyway. The gate message points at `xt doctor` and `docs/migration/beads-to-substrate.md` instead of "upgrade xt". `xt update --json` reports `migration.status: transition-pending` with a `transition` object.

## Pi extensions

- **`substrate-suggest` (82df0b34 · CORE-2344, #694).** New optional extension (`required: false`). At `agent_end` it suggests at most one `sb` update per turn as a wake card, based on claim TTL, checkpoint staleness, journal delta and attestation currency. It is advisory only and fails open.
- **`/xtprompt` with thinking models (f9d26e36).** Requests use provider-neutral `reasoning: 'low'`, so thinking-by-default models no longer spend the 1600-token budget on thinking and return no `<xtprompt>` block.

## Release engineering

- **npm trusted publishing (3ad1735a · XTRM-596, #682).** `publish.yml` publishes with OIDC and `--provenance`. `NPM_TOKEN` is no longer used.
