# v0.14.0 — XTRM agent host, Specialists 4.x compatibility, one hook dispatcher per event

Package: `xtrm-tools@0.14.0` · Extensions: `@jaggerxtrm/pi-extensions@0.14.0`

> Accepts Specialists `>=3.21.0 <5`, which includes the `@jaggerxtrm/specialists` 4.x line. The vendored Specialists payload remains pinned to `master@5a661d16` (git-blob-sha1 digest).

## Summary

0.14.0 adds the **XTRM agent host**. `xt host` is a per-user daemon that collects live session state from Pi and Claude Code over a local socket. It indexes stopped sessions from their journals. It serves a small HTTP API that launches sessions, resolves `@` references, and, when enabled, pairs remote devices. A new managed Pi extension (`xtrm-agent-host`) and a new Claude Code hook (`agent-host-reporter.mjs`) feed it. The wire protocol is defined as JSON Schemas in `@xtrm/contracts` 0.12.0, which the CLI bundles.

Two operational fixes ship with it. Interactive worktree launch accepts Specialists 4.x again, so `XTRM_SKIP_RUNTIME_COMPAT=1` is no longer necessary. Claude Code hooks run as one dispatcher process per hook event instead of up to four processes.

This is a minor bump, not a patch. It adds a new CLI command group (`xt host`), a new managed Pi extension and a new managed Claude hook. No CLI verb was removed.

## XTRM agent host (`xt host`)

- **Agent host daemon (73da09da · XTRM-563).** `xt host start|status`. The producer socket accepts NDJSON `xtrm.agent-event.v1` frames and sends `xtrm.agent-command.v1` frames on `$XDG_RUNTIME_DIR/xtrm/agent-host.sock` (fallback `~/.xtrm/run/agent-host.sock`). The socket has mode `0600`. The host takes over a stale socket only when no host answers on it. The live session registry is derived from pushed frames.
- **`xt host ensure --json` (f71052dc · XTRM-567).** Starts the per-user host when none answers, or reuses the running one. It prints exactly one `xtrm.agent-host-ensure.v1` object. The started host is detached and logs to `~/.xtrm/run/agent-host.log`, so the SSH session that started it can exit.
- **History-only sessions (1bcf7f34 · XTRM-565; 2b5a0edd · XTRM-580).** The host watches the Pi and Claude Code session journal directories and re-reads only appended bytes. It serves stopped sessions as `history_only` through `GET /v1/sessions`. A provider root created after host start is now picked up without a restart.
- **Launch endpoint (7dbdc04b · XTRM-566).** `POST /v1/launch` starts `xt pi … --no-attach --json` or bare `pi` in a new detached tmux session, and binds the pane to its session. Arguments are argv arrays. Unknown options and a non-directory `cwd` are rejected with 400.
- **Typed `@` reference resolution (8c0d9915 · XTRM-570).** `POST /v1/references/resolve` resolves host-owned reference kinds against the session. `@file:` reads return a sha256 content revision. Paths outside the session `cwd`, `..` escapes and symlinks that resolve outside it are rejected.
- **Direct mode with device pairing (3e1e973a · XTRM-568).** Off by default. With `xt host start --direct --direct-host <name>`, tailnet clients behind an HTTPS front reach the same loopback listener. The host binds only `127.0.0.1`. A request counts as local only when it arrives on loopback with a loopback `Host` header and no proxy forwarding header. Every other request needs a bearer device token, except `POST /v1/pair`. Pairing is one-time and device sessions are revocable.

## Producers

- **`xtrm-agent-host` Pi extension (1f243872 · XTRM-564).** A managed extension in `@jaggerxtrm/pi-extensions`. It sends `session_identity` first on every connection, then lifecycle, turn, message and tool events to the host socket. The socket path can be overridden with `XTRM_AGENT_HOST_SOCKET`.
- **Tool origin classification (acffbeda · XTRM-571; 24ecda9d · XTRM-575).** Every `tool_execution_*` event carries an `origin` derived from the tool's registration record, never from the tool name alone. `origin.extension` is the registering package's `package.json` name, so path installs no longer leak an absolute install path.
- **Locally resolved UI requests (ac1e7fbd · XTRM-574).** A Pi extension UI request that is answered, cancelled or timed out in the terminal now emits `extension_ui_resolved`. The host no longer keeps the session in `waiting_for_input` with a stale prompt.
- **Claude Code hook reporter, presence only (7196cdc7 · XTRM-569; 68925ce2 · XTRM-579; 7e4216e1 · XTRM-583).** `.xtrm/hooks/agent-host-reporter.mjs` reports Claude sessions to the host with one short connection per hook. The 300 ms delivery budget now starts when the hook begins its work, not at Node boot, so loaded machines no longer drop every event.

## Protocol: `@xtrm/contracts` 0.12.0

- **Agent host schemas (30ab8890 · XTRM-562).** `xtrm.agent-event.v1`, `xtrm.agent-command.v1` and `xtrm.agent-host-api.v1`, with TypeScript types, ajv validators, NDJSON helpers and round-trip fixtures. Event payloads were verified against `@earendil-works/pi-coding-agent` 1.0.0.
- **Inline schemas for bundled consumers (1c11efb4).** The validators read `../schemas` from disk at module load, which crashed every `xt` command in the bundled CLI. The schemas are now imported statically so bundlers inline them.

`@xtrm/contracts` is a build-time dependency of the CLI and is bundled into `cli/dist`. It is **not published to npm by this release**; `xtrm-tools` and `@jaggerxtrm/pi-extensions` do not declare it as a runtime dependency.

## Runtime compatibility and hooks

- **Accept Specialists 4.x (PR #677 · 7210fe11).** Core declared `>=3.21.0 <4`, so `xt claude` and `xt pi` rejected every new worktree after `@jaggerxtrm/specialists` 4.0.0 shipped, unless `XTRM_SKIP_RUNTIME_COMPAT=1` was set. 4.0.0 removes surfaces Core does not reference, so the range is now `>=3.21.0 <5`.
- **One dispatcher process per hook event (PR #678 · e6043e4e · CORE-2339).** The Claude hook template registered up to four `xt` processes per Edit event and two per Bash event, each paying full interpreter startup. All checks for an event now run in one `dispatch.mjs` process. The agent-host reporter is the one documented standalone exception, because it is a presence producer, not a check (2c77eb21).
- **Keep `xt pi` launch theme sync off the global `~/.pi/agent` (497303ae · XTRM-581).** The launch preflight resolved its agent dir from a module-load snapshot and ignored `PI_CODING_AGENT_DIR`. Isolated launches and worktree builds re-pointed the operator's theme links at the worktree. The dir is now resolved per call: `PI_CODING_AGENT_DIR` > `PI_AGENT_DIR` > `~/.pi/agent`.

## Pi 1.0 SDK alignment

- **Resolve the Pi 1.0 SDK in-repo (8f89de81 · XTRM-586).** `pi-extensions` imported the Pi SDK packages without declaring them, so Node and `tsc` resolved a stray 0.84.4 copy from a parent directory. They are now `*` peers plus `^1.0.0` devDependencies, and `scripts/check-pi-sdk-resolution.mjs` guards the resolution.
- **Typecheck clean against Pi 1.0 (8c8c1900 · XTRM-588).** Handlers for events Pi 1.0 never emits (`session_switch`, `session_fork`) are removed; `session_start` already covers `/new`, `/resume` and `/fork`.
- **Gate the Pi SDK in `prepublishOnly`, not in `build` (ce3356d3 · XTRM-593).** The installer-surface smoke reinstalls only the CLI workspace tree, which drops the root Pi SDK devDependencies. `check:pi-sdk` and `typecheck:pi-extensions` now run in `prepublishOnly`, so a release is still gated on them.

## Upgrade notes

- **Remove `XTRM_SKIP_RUNTIME_COMPAT=1`** if it was set only to launch worktrees with Specialists 4.x.
- **`xt host` is opt-in.** No daemon starts unless `xt host start` or `xt host ensure` runs. Direct mode needs `--direct`.
- **Refresh managed assets with `xt update --apply`** to receive the `xtrm-agent-host` Pi extension, the agent-host reporter hook and the single-dispatcher hook template.
