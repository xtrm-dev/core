## Target principle under test

> Core consumes the published Substrate contract; Core does not derive Substrate authority independently.

**Verdict: FAILS on three independent axes.**

1. **Package identity is stale.** Core contains **zero** occurrences of `@jaggerxtrm/substrate`. Every reference still says `@xtrm/substrate`, including a live runtime filesystem probe path. Against a real (renamed) Substrate checkout, `integrations/setup.ts`'s own `resolveSubstrateDir` rejects the source by package name — and Core's test fixtures never catch it because they stub `setup.ts`.
2. **Core owns project identity.** `xt init` branches on operator-supplied `--sb-create-project PREFIX:Name` and calls `sb project create --prefix/--name` + `sb project link --project <id>`. ADR `sbcloseout4` §18 labels the whole `sb project *` family "advanced/recovery surfaces … not the normal onboarding workflow", and §19 states "Core must delegate Project creation/resolution to Substrate" with `sb init --json` in the normal flow. Core never invokes `sb init`.
3. **The consumed `sb` surface is pinned to 0.1.x and is already wrong for main.** Core's `SbDoctorData` matches published 0.1.2 exactly, and its `project link` invocation only works on 0.1.2. On main, `sb project link` without `--project` is a hard error and `data.link`/`data.repository` changed shape.
